## 해석과 한계

이 기록에서는 lnt 지도가 첫 소스 편집 전의 탐색을 줄였다는 신호가 보이지 않는다.
- 같은 기간 ln 과 비-ln 의 중앙값은 2~3 회로 같은 범위에 있다. 평균 차의 95% 구간은 0 을 포함한다.
- 이 결과는 상위 5% 제외, 언어 맞춤, 긴 세션 제외, 분할 방식 변경, 세션 단위 누적에서 그대로였다.
- 방향만 보면, 개요형 컨텍스트 파일이 대상 파일에 닿기 전 단계를 의미 있게 줄이지 못했다는 ETH 연구 결과와 같다. 다만 설정이 다르다. 그 연구는 벤치마크 과제를 새 저장소에서 풀었고, 이 기록은 익숙한 프로젝트에서 이어지는 대화다.
- 그렇다고 이 자료가 "효과 없음"을 보여 주지도 않는다. 아래 교란 요인이 집단 차이보다 크고, 이 자료로는 그것들을 떼어 낼 수 없다.

- 프로젝트와 과제 종류가 다르다.
  - ln 세션의 첫 편집은 Python/Rust 가 많고, 비-ln 은 JS/TS/HTML 프런트엔드가 많다.
  - 프로젝트별 중앙값은 0 에서 6 까지 흩어져 있어 집단 차이보다 크다.
  - fishmathpics 한 곳이 ln 편집 과제의 42% (591건 중 247건)를 차지한다.
  - 어떤 프로젝트에 ln 을 들일지는 사용자가 골랐다. 무작위 배정이 아니다.
- 모델과 도구 판이 한 달 사이에 바뀌었다.
  - 09-22 무렵 fable-5-1/opus-5 에서 opus-5-5 로 바뀌었고, Claude Code 는 2.1.27 에서 2.1.30 이 됐다.
  - fishmathpics 의 도입 전 과제는 모두 이전 모델의 것이다.
  - 같은 모델 안에서도 마지막 주에 두 집단 모두 탐색이 늘었다. 과제 구성이나 작업 습관이 바뀐 것으로 보이며, 이 추세가 시기 비교에 섞인다.
- lnt 자체가 0.1 에서 0.8 로 바뀌었다.
  - 지도의 형식과 훅을 부르는 방식(`python -m lntools` 에서 `lnt` 로)이 바뀌었다.
  - 훅이 실패한 기간이 있다: gatesplan-fishmathpics 10-08 이후, aigirlshorts 일부.
  - 패키지가 `src/` 밖에 있는 codefish 는 지도를 받지 못했다.
  - 그래서 "ln 세션"은 한 가지 처치가 아니다. 반대로 비-ln 쪽 "ln 프로젝트, 출력 없음" 세션에도 ln 구조와 CLAUDE.md 안내는 그대로 있었다.
- 표본이 작다.
  - 같은 프로젝트의 전후 비교에서 "전" 쪽은 codefish 2개 세션 6건, fishmathpics 5개 세션 28건, problem-parameterizer 2개 세션 12건이다.
  - 중앙값이 0~4 의 작은 정수라서 한두 과제만 바뀌어도 값이 움직인다. 셸 루프 판정을 고쳤을 때 fishmathpics 도입 전 중앙값이 0 에서 2 로 바뀌었다.
- 과제를 나누는 방식이 결과에 영향을 준다.
  - 사용자는 세션 첫 프롬프트에서 주로 조사와 계획을 시키고, 다음 프롬프트에서 편집을 맡긴다 (첫 과제의 편집 비율 6%).
  - 그래서 과제 단위 지표는 앞 과제의 탐색을 놓친다. 탐색 0회 과제가 약 20%인 것도 이 때문이다.
  - 세션 단위 누적으로 보완했지만 결론은 같았다.
